# Contributing to BlackMint

Thank you for your interest in contributing to BlackMint.

## Current Status

BlackMint is currently in **private beta**. The codebase will be open-sourced following the public launch. Watch this repository to be notified when it opens for public contributions.

## How to Contribute

### Reporting Bugs

Before submitting a bug report, please check existing issues to avoid duplicates. When submitting a bug report, include a clear and descriptive title, steps to reproduce the issue, expected behaviour vs actual behaviour, screenshots if applicable, and your browser and operating system.

### Suggesting Features

Feature suggestions are welcome. Please open an issue with a clear description of the feature, the problem it solves, how you envision it working, and any relevant examples from other products.

### Pull Requests

1. Fork the repository
2. Create a feature branch from `main`
3. Make your changes following the code style guidelines below
4. Write clear, descriptive commit messages using conventional commits format — for example `feat: add whale alert notifications` or `fix: resolve risk score calculation`
5. Open a pull request against `main` and fill in the pull request template

## Code Style Guidelines

Write clean, readable, self-documenting code. Keep functions small and focused on a single responsibility. Use explicit TypeScript types and avoid `any` where possible. Use interfaces over type aliases for object shapes, and follow existing naming conventions in the codebase.

## Design System

BlackMint uses a consistent design system. When contributing UI, use the following: Accent `#C8FF00` (lime green), Background `#0c0e13`, Panel `#15171e`, and Fonts Space Grotesk for UI and JetBrains Mono for code and wallet addresses.

## Code of Conduct

By contributing to BlackMint, you agree to maintain a respectful and professional environment. We have zero tolerance for harassment, discrimination, or abusive behaviour of any kind.

## Questions

For questions about contributing, open a GitHub Discussion or reach out via the contact details in the README.
